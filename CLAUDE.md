# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Jessica — фоновый уведомитель по двум облигационным портфелям хозяйки (Т-Инвестиции и Альфа).
Это не библиотека и не сервис: launchd будит её ежечасно, она пересобирает данные и пишет
в Telegram о купонах, погашениях, офертах и значимых новостях по эмитентам.

Ключевое разделение: **код здесь, данные и секреты — в `~/Documents/Tracking/Invest/`**
(переопределяется переменной `JESSICA_HOME`, что и используется в тестовых прогонах).
Репозиторий можно снести и переустановить, не потеряв ни портфелей, ни истории отправок.

## Команды

```bash
jessica doctor                     # проверка источников, связи, наличия выгрузок
jessica import                     # собрать состав: Т из T-Invest API, Альфа из выгрузки → holdings.json
jessica refresh                    # собрать состав и пересобрать календарь → schedule.json (~40 c)
jessica calendar --days 30         # ближайшие выплаты
jessica check --dry-run --date ГГГГ-ММ-ДД   # что ушло бы в эту дату, без отправки
jessica news --dry-run             # новости, без отправки
jessica market --dry-run           # индекс МосБиржи и курс доллара, без отправки
jessica run                        # один проход по расписанию (его запускает launchd)
```

`jessica` — обёртка в `~/.local/bin/`, вызывающая `~/Projects/jessica/.venv/bin/python -m jessica`.
Скрипты и разовые расчёты запускай тем же интерпретатором: системный Python зависимостей не видит.

Агент по расписанию: `~/Library/LaunchAgents/com.alferova.jessica.plist`,
перезагрузка — `launchctl unload && launchctl load -w`.

`--dry-run` есть у `check`, `news` и `market` — пользуйся им. Без него `check` и `news`
отправят владелице настоящее сообщение и запишут его в `sent.json`, после чего настоящее
уведомление в этот день уже не придёт. У `market` наоборот: отметку в `last_run.json`
ставит только `run`, поэтому вручную запущенная сводка уйдёт лишним сообщением
и не помешает утренней.

## Поток данных

```
T-Invest API → sources/tinvest.py ┐
выгрузки Альфы ───────────────────┴→ holdings.py → state/holdings.json   (позиции: ISIN, количество, тип, эмитент)
                                          ↓
   sources/smartlab.py → calendar.py → state/schedule.json (купоны, погашения, оферты, details)
                                          ↓
   sources/news.py  →  events.py  →  notify.py  →  Telegram
                          ↑
                    state/sent.json (дедупликация)

   sources/market.py → events.py → notify.py → Telegram    (утренняя сводка)
        индекс (ISS → Alor → smart-lab) + курс доллара (ЦБ РФ) —
        мимо holdings.json и schedule.json:
        сводка про рынок вообще, а не про портфель
```

Правило, на котором держится вся конструкция: **логика уведомлений работает только
с `holdings.json` и `schedule.json` и ничего не знает об источниках.** Смена источника —
правка одного файла в `sources/`, а не всей программы. Не тащи HTTP-запросы в `events.py`.

`run` идемпотентен: `sent.json` хранит ключи `isin|тип|дата|за_сколько_дней|портфель`,
поэтому повторный запуск в тот же час ничего не задваивает, а пропущенный из-за сна
машины час догоняется на следующем проходе. Разовые за день рассылки — события дня,
календарь на месяц, сводка по рынку — отмечаются не в `sent.json`, а датами
в `last_run.json`: дедуплицировать там нечего, достаточно знать, что за сегодня уже было.

## Сетевые ограничения — они определяют архитектуру

Машина физически в России, но постоянно под европейским VPN. Проверено:

- `invest-public-api.tbank.ru` — **открыт**, но цепочка сертификата от Russian Trusted Root CA
  (Минцифры). Корень лежит в `jessica/certs/` (SHA-256 `D2:6D:2D:…:CF:31`, полный — в спеке
  `docs/superpowers/specs/2026-09-10-tinvest-holdings-design.md`) и передаётся в `verify=`
  только в `sources/tinvest.py`; в системное хранилище не ставится. Режется по IP выходного
  узла VPN так же, как ISS. Токен read-only, в `config.yaml`, блок `tinvest`.
- `iss.moex.com` и `www.moex.com` — **режутся по IP выходного узла VPN, и
  непредсказуемо**: 9 сентября 2026 ISS отвечал ~1 с (выход в США), 10 сентября
  из-под того же VPN рвётся на TLS (`SSL_ERROR_SYSCALL` / `SSLEOFError`) — узел
  у провайдера гуляет между разрешёнными и заблокированными адресами. Портфельная
  часть Jessica и так построена так, чтобы без ISS обходиться. Индекс МосБиржи
  для утренней сводки теперь берётся с фолбэком: **ISS → Alor → smart-lab**
  (см. `sources/market.py`), поэтому молчание ISS сводку больше не рвёт.
  Новостной экспорт биржи (`www.moex.com/export/news.aspx?cat=100`) с того же
  хоста — когда `www.moex.com` заблокирован, он тоже молчит, и это штатно.
- `api.alor.ru` — открыт и быстр (~0,05 с), ключа не требует. Эндпоинт
  `/md/v2/history?symbol=IMOEX2&exchange=MOEX&tf=D` отдаёт дневные свечи IMOEX2
  (текущая — ещё формируется, предыдущая — закрытие «вчера»). Данные отстают
  минут на 15 — для сводки в 10 утра не важно. Первый запасной источник индекса.
- `cbr.ru` — открыт и быстр (~0,1 с). Официальный курс доллара берётся оттуда
  (`scripts/XML_dynamic.asp`, код валюты `R01235`), а не с Мосбиржи: так курс
  доходит до владелицы, даже когда ISS молчит.
- `e-disclosure.ru` — JS-заслон Playwright проходит, но **за ним капча**. Её не обходить.
  Вместо этого факт события берётся из ленты, а в сообщение кладётся ссылка на поиск
  по компании — открывает её человек.
- `smart-lab.ru` — рабочий источник. Купоны на `/q/bonds/<ISIN>/coupons/`, а погашение,
  оферта, номинал и признак амортизации — на карточке `/q/bonds/<ISIN>/` **плоским текстом,
  не таблицей** (см. `PATTERNS` в `sources/smartlab.py`). Ещё в шапке главной висит
  таблица индексов — оттуда берётся **IMOEX** (не IMOEX2, его там нет) как последний
  запасной источник для утренней сводки, когда молчат и ISS, и Alor.
- Новостных лент две, список — `FEEDS` в `sources/news.py`. `smart-lab.ru` даёт телеграфные
  заголовки корпоративных событий, под них и писались `CATEGORIES`; `thebell.io/feed` пишет
  развёрнутыми фразами и больше про макро. **The Bell заблокирован в РФ и держится на VPN** —
  отваливается он чаще прочих, и это штатно. Ленты опрашиваются порознь, молчание одной
  не лишает слова вторую; увидеть молчащую можно только в `jessica doctor`.
- ОФЗ ищутся по биржевому коду (`SU26253RMFS3`), а не по ISIN — отсюда параметр `*alternates`.
- VPN изредка обрывает соединение. Всё, что ходит в сеть, должно переживать разовый
  таймаут повтором, а не считать его отказом.

`browser.py` (Playwright) написан и работает, но в рабочем цикле сейчас не задействован —
единственный источник, ради которого он был нужен, закрыт капчей.

## Брокерские выгрузки: подводные камни

Состав Т берётся из T-Invest API (облигации и акции брокерского счёта, ИИС не учитывается),
состав Альфы — **только** из выгрузок; руками ничего не заносится. Если API не ответил,
в `holdings.json` остаётся прошлый блок с `stale: true`, а `run` повторяет сбор раз в
`schedule.refresh_retry_hours` (3 ч) и пересобирает календарь, только если состав изменился.
Сведения о бумагах кэшируются в `state/tinvest_instruments.json`. Для выгрузок в `holdings.py`
точный парсер Альфы и общий запасной.

- **Альфа** (zip с xlsx, имена внутри архива в cp866): лист «Динамика позиций», количество
  и название в одной строке, а **ISIN — отдельной строкой под ней**; тип бумаги задан
  разделом таблицы («Акции», «Облигации», «Прочее»).

Колонки ищутся по тексту заголовка, а не по номеру: брокеры меняют вёрстку.
Нераспознанные строки попадают в `skipped` и печатаются, а не теряются молча.

## Правила уведомлений (`events.py`)

Фильтр по типу бумаги несимметричен намеренно: держателю **облигации** идут купоны,
погашения, оферты, дефолты, правовые риски, рейтинги и отчётность, но **не** дивиденды
и допэмиссии; держателю **акции** — всё. Категория `legal` (аресты, уголовные дела,
банкротство, санкции) для облигаций критична: платить нечем становится раньше, чем это
признают дефолтом.

Чтобы новость ушла, нужны **два** условия сразу: компания упомянута И категория значима.
Одного совпадения имени мало — в ленте полно омонимов (новость про самолёты цепляет
компанию «Самолет»). Маркеры категорий — регулярные выражения, потому что «иск» сидит
внутри «поиска», а «суд» внутри «судна».

Маркеры компании строятся из `name` и `issuer` позиции (`news.company_markers`). У Т они
приходят из API: эмитент — `borrowName`, а без него `brand.company`; у секьюритизаций —
само СФО, а не банк-оригинатор. `ГК` в `STOP_ABBR`, `кредитный`/`поток` в `STOPWORDS`.
`import` печатает `⚠ без маркеров` для бумаг, по которым новости не найдутся (кроме госбумаг
и СФО). Для акций есть категория `governance`: совет директоров, смена руководства, собрания
акционеров, слияния, делистинг.

Маркеры бывают двух видов. `CATEGORIES` в `sources/news.py` — свод формулировок, верных
для любой ленты. `SOURCE_CATEGORIES` — добавка к одной ленте: у The Bell неплатёж описан
развёрнуто («проблемы с выплатами»), и в общей таблице такая фраза цепляла бы обзоры
рынка потребкредитования на smart-lab. Обе таблицы сливаются в `_compile` с сохранением
порядка категорий; завести в добавке новую категорию нельзя — их набор знает
`relevant_news`, а он про ленты не знает ничего.

Даты амортизационных выплат неизвестны: источник даёт только факт амортизации. Такие
выпуски помечаются словами, без цифры. Цен покупки и котировок нет вообще — доходность
к погашению посчитать нельзя, только денежные потоки.

## Утренняя сводка по рынку

Отдельная от портфеля рассылка: индекс МосБиржи и официальный курс доллара,
ежедневно в `schedule.market_hour` (сейчас 10:00 МСК, событиями дня занят час раньше).
Собирается в `events.market_digest`, числа берутся в `sources/market.py`.

- Индекс — **IMOEX2**, а не IMOEX: он считается за весь торговый день, включая
  утреннюю и вечернюю сессии, поэтому к десяти утра по нему уже есть движение.
  Исключение — запасной smart-lab: там только IMOEX, и сводка тогда честно
  называет в шапке «IMOEX», а не «IMOEX2» (`_index_block` берёт имя из `secid`).
- Индекс достаётся с фолбэком по трём источникам, первый ответивший выигрывает:
  `_index_iss` (реальное время, два запроса — текущее значение и история),
  `_index_alor` (дневные свечи, один запрос), `_index_smartlab` (шапка главной,
  один запрос). Все три возвращают одинаковый словарь.
- Изменение считается к **закрытию предыдущего торгового дня**, а не к полю
  `LASTVALUE`/`CURRENTVALUE` текущих торгов: у IMOEX2 они расходятся из-за вечерней
  сессии. У ISS и Alor закрытие берётся из истории свечей; у smart-lab абсолютного
  «вчера» нет — оно восстанавливается из процента (тот округлён до 0,1 %),
  а дата закрытия принимается за предыдущий будний день.
- База изменения называется датой («к закрытию 8 сентября»), а не словом «вчера»:
  после праздников предыдущий торговый день отстоит на неделю.
- Курс — **официальный ЦБ**, так решила хозяйка: биржевой не нужен. ЦБ ставит курс
  по рабочим дням, и запись от пятницы действует все выходные, поэтому «предыдущий»
  курс — это предыдущая запись ряда, а не предыдущий календарный день.
- Индекс и курс независимы, и молчание одного сводку не отменяет: строка индекса
  заменяется на «Мосбиржа не ответила» (только если промолчали все три источника).
  Пусто возвращается, лишь когда молчат и индекс, и ЦБ, — тогда
  `run` не ставит отметку и повторяет попытку через час.
- В субботу и воскресенье сводка не уходит: торгов не было, пришло бы то же пятничное
  число третий раз подряд. Включается флагом `schedule.market_weekends`.

## Сообщения в Telegram

Разметка — `parse_mode=HTML` и только `<b>`, `<i>`, `<code>`, `<a>`. Ни заголовков,
ни списков, ни горизонтальных линий там нет, поэтому структуру держат эмодзи и символьный
разделитель `RULE`. Текст эмитентов прогоняй через `notify.escape` — в названиях
встречаются кавычки и амперсанды. Длинные сообщения режутся по границам строк в `notify._chunks`.

Тесты — `unittest`, без сети: `.venv/bin/python -m unittest discover -s tests`. Фикстуры
T-Invest синтетические; настоящие ответы API — только в `~/Documents/Tracking/Invest/tinvest-recordings/`

**Секреты агенту не показываются.** Claude Code запрещено читать `config.yaml` и файлы
с токенами (`deny` в `~/.claude/settings.json`). Токены читает только код Jessica при запуске,
проверка — через вывод `jessica doctor`. Правки конфига делает хозяйка.
