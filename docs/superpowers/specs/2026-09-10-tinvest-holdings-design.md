# Состав портфеля Т-Инвестиций из T-Invest API

Дата: 10 сентября 2026. Статус: дизайн согласован, замечания ревью внесены,
ждёт финального просмотра хозяйкой.

## Зачем

Состав портфелей приходит только из брокерских выгрузок, которые хозяйка
кладёт руками. Выгрузка устаревает сразу: 10 сентября `holdings.json`,
собранный из выгрузки по 3 сентября, показывал 30 облигаций РЖД
(`RU000A10C8C0`), а в счёте их 32.

С 9 сентября 2026 Т-Инвестиции открыли всем клиентам API и MCP с токеном
уровня «только чтение». Спайк 10 сентября показал: `invest-public-api.tbank.ru`
с этой машины отвечает за 0,02–0,08 с, а `GetAccounts`, `GetPortfolio`,
`GetOperationsByCursor`, `BondBy` и `GetAssetBy` отдают всё нужное для
`holdings.json`. Из 11 облигаций 10 совпали с выгрузкой до штуки, расходится
только РЖД — в пользу API.

## Принятые решения

1. **API — единственный источник состава портфеля Т.** Точный парсер выгрузок
   Т-Банка удаляется, выгрузка Т больше не нужна. Альфа остаётся на выгрузках.
2. **Учитывается только брокерский счёт** (`ACCOUNT_TYPE_TINKOFF`). ИИС,
   инвесткопилка и прочие счета в Jessica не попадают — как и сейчас,
   когда в выгрузке только брокерский счёт.
3. **Запрос к API делается при сборке `holdings.json`**, то есть в `import`,
   в `refresh` (теперь он тоже собирает состав) и в суточном обновлении `run`.
4. **Отказ API мягкий:** остаётся прошлый Т-раздел с пометкой `stale`, календарь
   собирается на нём, команды не падают.
5. **`run` повторяет обновление раз в 3 часа**, пока Т не обновится; `refreshed`
   ставится только при успехе. На повторных попытках календарь пересобирается,
   только если состав изменился.
6. **`run` остаётся ежечасным:** новости и утренние рассылки приходят в срок,
   а к брокеру `run` идёт только при обновлении состава.

## Сетевая оговорка

API брокера режется по IP выходного узла VPN так же, как ISS Мосбиржи
(`SSL: UNEXPECTED_EOF_WHILE_READING`). Узел в пуле netcup меняется сам по себе,
иногда раз в несколько минут, и часть узлов пропускают, часть нет. Дизайн это
учитывает: отказ мягкий, ретраи раз в 3 часа, число запросов за один сбор
сведено к минимуму (см. кэш бумаг). Надёжное решение — маршрутизация tbank
и MOEX в VPN мимо заблокированных узлов, это задача хозяйки и в эту спеку
не входит.

## Не входит

- Торговля, переводы, любые пишущие методы. Токен только read-only.
- ИИС и другие счета, кроме брокерского.
- Календарь из API. `BondBy`/`GetAssetBy` отдают погашение, амортизацию,
  номинал, а купоны и оферты есть в отдельных методах, но `calendar.py` пока
  остаётся на smart-lab.
- Сверка пришедших купонов с `schedule.json` через `GetOperationsByCursor`.
- Портфель Альфы.

## Компоненты

### `jessica/sources/tinvest.py` (новый)

Источник, как остальные в `sources/`: ходит в сеть, возвращает простые данные,
про `holdings.json`, файлы состояния и сообщения ничего не знает.

```python
def fetch_bonds(
    token: str, *, account: str | None = None, known: dict[str, dict] | None = None
) -> list[dict] | None
```

`known` — уже известные сведения о бумагах, ключ `instrumentUid`, значение —
словарь `isin`, `name`, `issuer`, `code`. Хранит и передаёт их `holdings.py`
(см. ниже); для бумаг из `known` модуль не делает запросов по инструменту.

Порядок вызовов (REST, `POST` на
`https://invest-public-api.tbank.ru/rest/tinkoff.public.invest.api.contract.v1.<Service>/<Method>`,
заголовок `Authorization: Bearer <token>`):

1. `UsersService/GetAccounts`. Если `account` не задан, берётся единственный
   открытый счёт типа `ACCOUNT_TYPE_TINKOFF`. Если таких несколько — ошибка
   в лог и `None`: гадать, чей счёт, нельзя.
2. `OperationsService/GetPortfolio(accountId)`. Остаются только позиции
   с `instrumentType == "bond"`, акции и валюта отбрасываются.
3. Только для облигаций, которых нет в `known`:
   - `InstrumentsService/BondBy` по `instrumentUid` — `isin`, `name`,
     `ticker`, `assetUid`;
   - `InstrumentsService/GetAssetBy(assetUid)` — эмитент
     (`asset.security.bond.borrowName`) и имя компании (`asset.brand.company`).

В обычный день состав не меняется, и сбор обходится двумя запросами
(`GetAccounts` + `GetPortfolio`) вместо ~23: меньше шансов попасть на
моргание VPN посреди цепочки.

Возвращаемый словарь на каждую облигацию:

| ключ | откуда |
|---|---|
| `uid` | `GetPortfolio.positions[].instrumentUid` — ключ для кэша |
| `isin` | `BondBy.isin` |
| `quantity` | `GetPortfolio.positions[].quantity` (units + nano / 1e9) |
| `name` | `BondBy.name` («Софтлайн 002Р-02») |
| `issuer` | `borrowName` («ПАО "Софтлайн"»); если пуст — `brand.company` («СофтЛайн»); если пусто и там — пустая строка |
| `code` | `BondBy.ticker`, если он отличается от ISIN (так приходит код ОФЗ `SU…RMFS…`), иначе пустая строка |

Сетевые правила:

- `verify=` — путь к `jessica/certs/russian_trusted_root_ca.pem`, и только для
  запросов этого модуля.
- Таймаут на запрос 10 с. Каждый запрос переживает разовый сбой: до 4 попыток
  с паузой 10 с. Когда API недоступен, модуль сдаётся на первом же запросе
  и возвращает `None`: при быстром обрыве TLS, как это делает VPN, это около
  35 с, при зависшем соединении — до 70 с.
- Ошибка на любом шаге (сеть, HTTP ≠ 200, неожиданный JSON), в том числе
  при запросе сведений о новой бумаге, — предупреждение в лог и `None`.
  Частичный портфель не возвращается никогда: половина состава хуже, чем
  вчерашний полный.
- Токен не попадает ни в лог, ни в текст исключений.

### `jessica/certs/russian_trusted_root_ca.pem` (новый)

Корневой сертификат Минцифры, которым подписана цепочка `*.tbank.ru`.
Публичный, не секрет, поэтому хранится в репозитории: переустановка работает
без ручного скачивания. SHA-256:
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.
В системное хранилище и в браузер не ставится. Тест сверяет отпечаток файла
с этим значением, так что случайная подмена файла не пройдёт незамеченной.

### `jessica/config.py`

- `Portfolio` получает поле `source: str = "reports"`; `reports_dir`
  становится необязательным (`Path | None`), для `source: tinvest` он не нужен.
- Новые свойства: `tinvest_token` (из `tinvest.token`), `tinvest_account`
  (из `tinvest.account`, может отсутствовать) и `refresh_retry_hours`
  (из `schedule.refresh_retry_hours`, по умолчанию 3).

### `jessica/holdings.py`

- Удаляются `_parse_tbank`, его ветка в `_detect` и запись в `PARSERS`.
  Парсер Альфы и общий запасной остаются. Вернуть Т на выгрузки после этого
  можно только через git — это осознанно.
- **Кэш сведений о бумагах** — `state/tinvest_instruments.json`,
  `{instrumentUid: {isin, name, issuer, code}}`. `collect()` читает его,
  передаёт в `fetch_bonds(known=…)` и после удачного сбора перезаписывает
  сведениями из ответа (проданные бумаги из кэша выпадают сами).
  Потеря файла не страшна: следующий сбор просто сделает запросы по всем
  бумагам заново.
- `collect()` выбирает источник по `portfolio.source`:
  - `reports` — `parse_portfolio()`, как сейчас;
  - `tinvest` — `tinvest.fetch_bonds(…)`, словари превращаются
    в `Position(kind=BOND, portfolio=key, …)`, поле `uid` в `Position`
    не переносится.
- Если `fetch_bonds` вернул `None`, `collect()` берёт блок этого портфеля
  из текущего `holdings.json` целиком и добавляет `stale: true`. Если прошлого
  блока нет (первый запуск), блок пустой, тоже со `stale: true`.
- `collect()` по-прежнему возвращает словарь `holdings` — по нему `run` узнаёт,
  было ли обновление полным и изменился ли состав.

Формат блока в `holdings.json`:

```json
"tinkoff": {
  "title": "Т-Инвестиции",
  "source_file": null,
  "format": "tinvest-api",
  "synced": "2026-09-10T15:02:11",
  "stale": false,
  "positions": [ … ],
  "skipped": []
}
```

`synced` — время последнего удачного запроса к API. При отказе он переносится
из прошлого блока без изменений: из него берётся дата в предупреждении.
У блоков из выгрузок `synced` и `stale` отсутствуют.

### Поиск компаний в новостях (`jessica/sources/news.py`)

Новость уходит, только если в заголовке упомянута компания, а упоминание
ищется по маркерам из `name` и `issuer` (`news.company_markers`). У API эти
строки другие, чем у выгрузки, так что маркеры меняются, хотя код `events.py`
остаётся прежним. Сравнение на названиях из спайка:

| бумага | сейчас (выгрузка) | из API, без исправлений | последствие |
|---|---|---|---|
| АЛИУМ | `алиу`, `АЛИУМ` | пусто | API пишет `АЛИУМ01Р1` слитно, регэксп кодов выпусков съедает слово целиком → новости об Алиуме перестают находиться |
| СФО ТБ-4 | `ТБ` | `кредитн`, `пото` | API называет выпуск «Кредитный поток 2.0» → «АКРА повысило кредитный рейтинг…» даёт ложное уведомление |
| РЖД | `РЖД`, `железн`, `доро` | `РЖД` | потеря некритичная |

Исправления:

- `issuer` берётся из `borrowName`, а при его отсутствии — из `brand.company`
  (см. таблицу в `tinvest.py`). Это возвращает маркеры АЛИУМу и РЖД.
- В `STOPWORDS` добавляются `кредитный` и `поток`: у секьюритизаций это
  название продукта, а не компании.
- В `STOP_ABBR` добавляется `ГК`. Это старая ошибка, не связанная с API:
  `\bГК\b` совпадает с любым «ГК ПИК» или «ГК Астра», и у Самолёта это давало
  ложные совпадения. У Самолёта остаётся основа `самол`, других бумаг, у которых
  `ГК` был бы единственным маркером, нет (проверено на обоих портфелях).
- `import` печатает `⚠ без маркеров: <бумага>` для каждой бумаги, у которой
  маркеры пусты: новости по такой бумаге молча не находятся, и это нужно видеть
  сразу. Исключения — госбумаги и секьюритизации (`СФО` в названии или
  эмитенте): у них маркеров не должно быть по определению. Уже сейчас так
  всплывёт акция «Т-Технологии» из портфеля Альфы: слово «технологии» стоит
  в стоп-словах, и новости о компании не находятся. Это давняя ошибка, в эту
  спеку её исправление не входит.

Обязательный шаг реализации: на настоящих ответах API сравнить маркеры каждой
облигации Т до и после перехода, выписать все расхождения и по каждому решить —
допустимо или требует правки. Переход в `config.yaml` делается только после
этой сверки.

### `jessica/cli.py`

- `import` — как сейчас, плюс для блока со `stale` печатает
  `⚠ Т-Инвестиции: API не ответил, состав от <synced или source_file>`
  и строки `⚠ без маркеров` (см. выше).
- `refresh` — сначала `holdings.collect()`, потом `cal.build()` всегда.
  То же предупреждение, если Т не обновился.
- `run` — условие суточного обновления выносится в чистую функцию

  ```python
  def refresh_due(state: dict, now: dt.datetime, retry_hours: int) -> bool
  ```

  Обновление нужно, если `state["refreshed"] != сегодня` и либо
  `state["refresh_attempt"]` отсутствует или не сегодняшний, либо с него
  прошло не меньше `retry_hours`.

  Когда обновление нужно:
  1. `collect()`;
  2. `cal.build()` — если это первая попытка за сегодня **или** состав
     изменился (сравниваются пары `isin` + `quantity` по всем портфелям до
     и после `collect()`); иначе календарь не трогается;
  3. `refresh_attempt = now` пишется всегда, `refreshed = сегодня` — только
     если ни один блок не `stale`.

  В день, когда API недоступен, это до 8 попыток сбора состава, но календарь
  пересобирается один раз, а не на каждой попытке.
- `doctor` — строка «выгрузка «Т-Инвестиции»» заменяется на
  `T-Invest API`: `OK  11 облигаций` или `СБОЙ  API не ответил`.
  Для портфелей с `source: reports` проверка выгрузки остаётся.

## Тесты

`tests/` сейчас пуста. Тесты на `unittest` из стандартной библиотеки,
без новых зависимостей и без сети, запускаются `python -m unittest discover tests`.

**Фикстуры.** Настоящие ответы API содержат состав портфеля и номер счёта,
а репозиторий лежит на GitHub. Поэтому:

- `scripts/record_tinvest_fixtures.py` сам берёт токен из `config.yaml`
  (через `Config.load()`) и сохраняет настоящие ответы API в
  `~/Documents/Tracking/Invest/tinvest-recordings/` — в папку с данными,
  не в репозиторий. Запускает его хозяйка или агент; агент читает только
  сохранённые ответы, в которых токена нет. По ним делается сверка маркеров.
- В репозиторий, в `tests/fixtures/tinvest/`, идут синтетические ответы той же
  структуры: четыре облигации (корпоративная с `borrowName`, ОФЗ, бумага со
  слитным названием вроде `АЛИУМ01Р1` без `borrowName`, секьюритизация),
  одна акция и рублёвый остаток; номер счёта и количества выдуманные.

Наборы тестов:

- `test_tinvest.py` — `requests.post` подменяется. Акции и валюта
  отфильтрованы; `quantity` из units/nano; эмитент из `borrowName`, а без него
  из `brand.company`; `code` у ОФЗ и пустой у корпоративных; бумаги из `known`
  не запрашиваются повторно (считаются вызовы); несколько счетов без `account`
  → `None`; ошибка на шаге `GetAssetBy` → `None`, а не частичный список.
- `test_holdings.py` — `collect()` во временном `JESSICA_HOME`: при `None`
  от API Т-блок берётся из прошлого `holdings.json` со `stale: true`
  и прежним `synced`, а блок Альфы собирается из выгрузки как обычно;
  первый запуск без прошлого файла даёт пустой `stale`-блок; кэш бумаг
  записывается после удачного сбора и не меняется после неудачного.
- `test_news.py` — маркеры: `ГК` не попадает в аббревиатуры; «Кредитный
  поток 2.0» не даёт основ `кредитн` и `пото`; слитное `АЛИУМ01Р1` с эмитентом
  из `brand.company` даёт маркер Алиума; ОФЗ по-прежнему без маркеров.
- `test_run.py` — `refresh_due`: новый день → да; сегодня уже `refreshed` → нет;
  неудачная попытка час назад → нет; три часа назад → да; попытка вчера → да.
  И решение о `cal.build()`: первая попытка дня → да; повторная без изменений
  состава → нет; повторная с изменением → да.
- `test_certs.py` — SHA-256 файла сертификата равен эталону из этой спеки.

## Миграция

Агент `config.yaml` не открывает и не правит: Claude Code запрещено его читать,
токен читает только код Jessica при запуске. Все правки конфига делает хозяйка.

1. **Отозвать токен, выданный на спайк:** он попал в историю сессии с агентом.
   Удалить `~/Documents/Tracking/Invest/tinkoff/tbank_mcp_token.txt`.
2. Выпустить новый read-only токен и вписать его в новый блок верхнего уровня:

   ```yaml
   tinvest:
     token: "t.…"
   ```

3. Запустить `scripts/record_tinvest_fixtures.py` и сделать сверку маркеров
   (раздел «Поиск компаний в новостях»). Дальше — только если сверка чистая.
4. Изменить блок `tinkoff` в `portfolios:` — `reports_dir` убрать,
   `source` добавить:

   ```yaml
   portfolios:
     tinkoff:
       title: "Т-Инвестиции"
       source: tinvest
     alpha:
       title: "Альфа"
       reports_dir: "alpha/reports"
   ```

5. **Добавить строку в существующий блок `schedule:`, а не создавать второй.**
   Если в файле окажутся два блока `schedule:`, PyYAML молча оставит только
   последний, и пропадут `morning_hour` и `market_hour`. Блок целиком должен
   выглядеть так:

   ```yaml
   schedule:
     morning_hour: 9           # час рассылки событий дня, МСК
     market_hour: 10           # час сводки по рынку
     refresh_retry_hours: 3    # как часто повторять сбор состава, если API не ответил
   ```

6. `jessica import` и сверка результата с выгрузкой: расходиться должно только
   РЖД, из строк `⚠ без маркеров` допустима только «Т-Технологии».
7. Папка `tinkoff/reports/` с выгрузками остаётся на месте, Jessica её больше
   не читает. Удалять или нет — решает хозяйка.
8. **Только после шага 4** из кода удаляется `_parse_tbank`. launchd запускает
   Jessica прямо из рабочего дерева, каждый коммит сразу боевой, и пока
   портфель Т в конфиге на `reports`, его выгрузку разбирает именно этот парсер.
   Удалить его раньше — значит отдать выгрузку Т запасному парсеру, и первый же
   `run` испортит состав.

## Риски

- **VPN.** Пока маршрутизация не настроена, Т может не обновляться сутками.
  Это видно в `import`/`refresh`/`doctor` и в `stale` в `holdings.json`.
- **Поиск новостей.** Смена источника названий меняет маркеры компаний;
  защита — сверка перед переходом, тесты и строка `⚠ без маркеров` в `import`.
- **Токен протухает** через 3 месяца без использования. При ежедневном `run`
  этого не случится, но если Jessica простоит 3 месяца, токен придётся
  выпустить заново. `doctor` покажет это как `СБОЙ` с HTTP 401.
- **Смена сертификата.** Корень Минцифры действует до 2032 года; если tbank
  перейдёт на другую цепочку, запросы упадут на проверке TLS, и `doctor`
  это покажет.
- **Формат ответов API.** Любое неожиданное поле приводит к `None`, а не к
  частичному составу, так что поломка видна сразу, а данные не портятся.
