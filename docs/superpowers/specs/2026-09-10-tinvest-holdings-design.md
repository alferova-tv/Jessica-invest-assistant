# Состав портфеля Т-Инвестиций из T-Invest API

Дата: 10 сентября 2026. Статус: дизайн согласован, ждёт ревью спеки.

## Зачем

Состав портфелей приходит только из брокерских выгрузок, которые хозяйка
кладёт руками. Выгрузка устаревает сразу: 10 сентября `holdings.json`,
собранный из выгрузки по 3 сентября, показывал 30 облигаций РЖД
(`RU000A10C8C0`), а в счёте их 32.

С 9 сентября 2026 Т-Инвестиции открыли всем клиентам API и MCP с токеном
уровня «только чтение». Спайк 10 сентября показал: `invest-public-api.tbank.ru`
с этой машины отвечает за 0,02–0,08 с, `GetAccounts`, `GetPortfolio`,
`GetOperationsByCursor`, `BondBy` и `GetAssetBy` отдают всё нужное для
`holdings.json`, остальные 10 из 11 облигаций совпали с выгрузкой до штуки.

## Принятые решения

1. **API — единственный источник состава портфеля Т.** Точный парсер выгрузок
   Т-Банка удаляется, выгрузка Т больше не нужна. Альфа остаётся на выгрузках.
2. **Запрос к API делается при сборке `holdings.json`**, то есть в `import`,
   в `refresh` (теперь он тоже собирает состав) и в суточном обновлении `run`.
3. **Отказ API мягкий:** остаётся прошлый Т-раздел с пометкой `stale`, календарь
   собирается на нём, команды не падают.
4. **`run` повторяет обновление раз в 3 часа**, пока Т не обновится; `refreshed`
   ставится только при успехе.
5. **`run` остаётся ежечасным:** новости и утренние рассылки по-прежнему
   приходят в срок, а к брокеру `run` идёт только при обновлении состава.

## Сетевая оговорка

API брокера режется по IP выходного узла VPN так же, как ISS Мосбиржи
(`SSL: UNEXPECTED_EOF_WHILE_READING`). Узел в пуле netcup меняется сам по себе,
иногда раз в несколько минут, и часть узлов пропускают, часть нет. Дизайн это
учитывает — отсюда мягкий отказ и ретраи раз в 3 часа. Надёжное решение —
маршрутизация tbank и MOEX в VPN мимо заблокированных узлов, это задача хозяйки
и в эту спеку не входит.

## Не входит

- Торговля, переводы, любые пишущие методы. Токен только read-only.
- Календарь из API. `BondBy`/`GetAssetBy` отдают погашение, амортизацию,
  номинал, а купоны и оферты есть в отдельных методах, но `calendar.py` пока
  остаётся на smart-lab.
- Сверка пришедших купонов с `schedule.json` через `GetOperationsByCursor`.
- Портфель Альфы.

## Компоненты

### `jessica/sources/tinvest.py` (новый)

Источник, как остальные в `sources/`: ходит в сеть, возвращает простые данные,
про `holdings.json` и сообщения ничего не знает.

```python
def fetch_bonds(token: str, *, account: str | None = None) -> list[dict] | None
```

Порядок вызовов (REST, `POST` на
`https://invest-public-api.tbank.ru/rest/tinkoff.public.invest.api.contract.v1.<Service>/<Method>`,
заголовок `Authorization: Bearer <token>`):

1. `UsersService/GetAccounts`. Если `account` не задан, берётся единственный
   открытый счёт типа `ACCOUNT_TYPE_TINKOFF`. Если таких несколько — ошибка
   в лог и `None`: гадать, чей счёт, нельзя.
2. `OperationsService/GetPortfolio(accountId)`. Остаются только позиции
   с `instrumentType == "bond"`, акции и валюта отбрасываются.
3. Для каждой облигации `InstrumentsService/BondBy` по `instrumentUid`:
   даёт `isin`, `name`, `ticker`, `assetUid`.
4. `InstrumentsService/GetAssetBy(assetUid)`: даёт эмитента
   `asset.security.bond.borrowName` («ПАО "Софтлайн"»).

Возвращаемый словарь на каждую облигацию:

| ключ | откуда |
|---|---|
| `isin` | `BondBy.isin` |
| `quantity` | `GetPortfolio.positions[].quantity` (units + nano / 1e9) |
| `name` | `BondBy.name` («Софтлайн 002Р-02») |
| `issuer` | `GetAssetBy…borrowName`, если его нет — пустая строка |
| `code` | `BondBy.ticker`, если он отличается от ISIN (так приходит код ОФЗ `SU…RMFS…`), иначе пустая строка |

Сетевые правила:

- `verify=` — путь к `jessica/certs/russian_trusted_root_ca.pem`, и только для
  запросов этого модуля.
- Таймаут на запрос 10 с. Каждый запрос переживает разовый сбой: до 4 попыток
  с паузой 10 с. Когда API недоступен, модуль сдаётся на первом же запросе
  и возвращает `None`: при быстром обрыве TLS, как это делает VPN, это около
  35 с, при зависшем соединении — до 70 с.
- Ошибка на любом шаге (сеть, HTTP ≠ 200, неожиданный JSON) — предупреждение
  в лог и `None`. Частичный портфель не возвращается никогда: половина состава
  хуже, чем вчерашний полный.
- Токен не попадает ни в лог, ни в текст исключений.

### `jessica/certs/russian_trusted_root_ca.pem` (новый)

Корневой сертификат Минцифры, которым подписана цепочка `*.tbank.ru`.
Публичный, не секрет, поэтому хранится в репозитории: переустановка работает
без ручного скачивания. SHA-256:
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.
В системное хранилище и в браузер не ставится.

### `jessica/config.py`

- `Portfolio` получает поле `source: str = "reports"`; `reports_dir`
  становится необязательным (`Path | None`), для `source: tinvest` он не нужен.
- Новые свойства: `tinvest_token` (из `tinvest.token`), `tinvest_account`
  (из `tinvest.account`, может отсутствовать) и `refresh_retry_hours`
  (из `schedule.refresh_retry_hours`, по умолчанию 3).

`config.yaml` (права 600, в git не попадает):

```yaml
    source: tinvest

    reports_dir: "alpha/reports"

  refresh_retry_hours: 3
```

### `jessica/holdings.py`

- Удаляются `_parse_tbank`, его ветка в `_detect` и запись в `PARSERS`.
  Парсер Альфы и общий запасной остаются.
- `collect()` выбирает источник по `portfolio.source`:
  - `reports` — `parse_portfolio()`, как сейчас;
  - `tinvest` — `tinvest.fetch_bonds(config.tinvest_token, account=…)`,
    словари превращаются в `Position(kind=BOND, portfolio=key, …)`.
- Если `fetch_bonds` вернул `None`, `collect()` берёт блок этого портфеля
  из текущего `holdings.json` целиком и добавляет `stale: true`. Если прошлого
  блока нет (первый запуск), блок пустой, тоже со `stale: true`.
- `collect()` по-прежнему возвращает словарь `holdings` — по нему `run` узнаёт,
  было ли обновление полным (нет ли блока со `stale`).

Формат блока в `holdings.json`:

```json
"tinkoff": {
  "title": "Т-Инвестиции",
  "source_file": null,
  "format": "tinvest-api",
  "synced": "2026-09-10T15:02:11",
  "stale": false,
  "positions": [ … ],
  "skipped": []
}
```

`synced` — время последнего удачного запроса к API. При отказе он переносится
из прошлого блока без изменений: из него берётся дата в предупреждении.
У блоков из выгрузок `synced` и `stale` отсутствуют.

### `jessica/cli.py`

- `import` — как сейчас, плюс для блока со `stale` печатает
  `⚠ Т-Инвестиции: API не ответил, состав от <synced или source_file>`.
- `refresh` — сначала `holdings.collect()`, потом `cal.build()`. То же
  предупреждение, если Т не обновился.
- `run` — условие суточного обновления выносится в чистую функцию

  ```python
  def refresh_due(state: dict, now: dt.datetime, retry_hours: int) -> bool
  ```

  Обновление нужно, если `state["refreshed"] != сегодня` и либо
  `state["refresh_attempt"]` отсутствует или не сегодняшний, либо с него
  прошло не меньше `retry_hours`. После `collect()` + `build()` всегда
  пишется `refresh_attempt = now`, а `refreshed = сегодня` — только если
  ни один блок не `stale`.
- `doctor` — строка «выгрузка «Т-Инвестиции»» заменяется на
  `T-Invest API`: `OK  11 облигаций, счёт …1639` или `СБОЙ  API не ответил`.
  Для портфелей с `source: reports` проверка выгрузки остаётся.

## Тесты

`tests/` сейчас пуста. Тесты на `unittest` из стандартной библиотеки,
без новых зависимостей и без сети, запускаются `python -m unittest discover tests`:

- `test_tinvest.py` — ответы API записаны в `tests/fixtures/tinvest/*.json`
  (из них вычищены номер счёта и прочее личное, токена там нет), `requests.post`
  подменяется. Проверяются: акции и валюта отфильтрованы; `quantity` из
  units/nano; эмитент из `borrowName`; `code` у ОФЗ и пустой у корпоративных;
  несколько счетов без `account` → `None`; ошибка на шаге `GetAssetBy` →
  `None`, а не частичный список.
- `test_holdings.py` — `collect()` во временном `JESSICA_HOME`: при `None`
  от API Т-блок берётся из прошлого `holdings.json` со `stale: true`
  и прежним `synced`, а блок Альфы собирается из выгрузки как обычно;
  первый запуск без прошлого файла даёт пустой `stale`-блок.
- `test_run.py` — `refresh_due`: новый день → да; сегодня уже `refreshed` → нет;
  неудачная попытка час назад → нет; три часа назад → да; попытка вчера → да.

Живая проверка после реализации: `jessica import` (в Т 11 облигаций,
РЖД — 32), `jessica refresh`, `jessica doctor`, `jessica check --dry-run`
на сегодня — уведомления те же, что до изменения.

## Риски

- **VPN.** Пока маршрутизация не настроена, Т может не обновляться сутками.
  Это видно в `import`/`refresh`/`doctor` и в `stale` в `holdings.json`.
- **Токен протухает** через 3 месяца без использования. При ежедневном `run`
  этого не случится, но если Jessica простоит 3 месяца, токен придётся
  выпустить заново. `doctor` покажет это как `СБОЙ` с HTTP 401.
- **Смена сертификата.** Корень Минцифры действует до 2032 года; если tbank
  перейдёт на другую цепочку, запросы упадут на проверке TLS, и `doctor`
  это покажет.
- **Формат ответов API.** Любое неожиданное поле приводит к `None`, а не к
  частичному составу, так что поломка видна сразу, а данные не портятся.
