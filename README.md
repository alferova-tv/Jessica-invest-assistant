# Jessica

Фоновый уведомитель по двум облигационным портфелям — Т-Инвестиции и Альфа.

Это не библиотека и не сервис. launchd будит Jessica ежечасно, она пересобирает
данные и пишет в Telegram: о купонах, погашениях, офертах, значимых новостях
по эмитентам и об утренней ситуации на рынке. Один получатель, одна машина, macOS.

Канал односторонний: Jessica только пишет владелице на `chat_id` из конфига
и не читает входящие. Посторонний, написавший боту, не получит ничего.

Устройство и причины принятых решений подробно описаны в [CLAUDE.md](CLAUDE.md) —
там же все подводные камни источников и брокерских выгрузок.

## Что приходит в Telegram

Разметка — `parse_mode=HTML`, и только `<b>`, `<i>`, `<code>`, `<a>`. Ни заголовков,
ни списков, ни горизонтальных линий Telegram не умеет, поэтому структуру держат
эмодзи и символьный разделитель. Примеры ниже собраны на выдуманных бумагах.

### События дня — в 9 утра

```
💰 КУПОНЫ СЕГОДНЯ
13 сентября
➖➖➖➖➖➖➖➖➖➖

🏦 Альфа
• Первая грузовая 003Р-01
   1 146,60 ₽  · 90 × 12,74
• Лизинг-Финанс БО-П18
   277,80 ₽  · 20 × 13,89

➖➖➖➖➖➖➖➖➖➖
💵 Итого: 1 424,40 ₽
```

Оферта приходит за 14, 7, 3 дня и в день события, погашение — за 7 дней и в день,
амортизация — за 3 дня и в день, купон — в день выплаты. Сроки задаются в конфиге.
У оферты в сообщении стоит отдельная строка «Нужно подать заявку брокеру»: её нельзя
проспать — не подашь заявку, останешься с бумагой, которую больше не собиралась держать.

Выпуски с амортизацией помечены значком 📉 и оговоркой словами, без цифры:
источник даёт только факт амортизации, а размер выплаты не раскрывает. Обещать
точную сумму, которой не знаешь, хуже, чем честно сказать, что придёт больше.

### Сводка по рынку — в 10 утра

```
📈 РЫНОК · 9 сентября
➖➖➖➖➖➖➖➖➖➖

📊 IMOEX2 — 2 276,07  · 11:30
   🔴 -3,52 (-0,15%)  · к закрытию 8 сентября

💵 Доллар ЦБ — 86,4730 ₽
   🟢 +0,28 ₽ (+0,33%)  · к 8 сентября
```

Индекс — IMOEX2, а не IMOEX: он считается за весь торговый день, включая утреннюю
и вечернюю сессии, поэтому к десяти утра по нему уже есть движение. Изменение
считается к закрытию предыдущего торгового дня, и база подписывается датой,
а не словом «вчера»: после праздников предыдущий торговый день отстоит на неделю.

В выходные сводка не уходит — торгов не было, пришло бы то же пятничное число
третий раз подряд.

### Новости по эмитентам — каждый час

```
📊 КРЕДИТНЫЙ РЕЙТИНГ
➖➖➖➖➖➖➖➖➖➖
АКРА подтвердило кредитный рейтинг ПАО «Эмитент» на уровне A+(RU),
прогноз «Стабильный»

Ваши бумаги:
• Эмитент 001Р-03

📰 источник   🏛 раскрытие
```

Дефолт или отчётность ждать до утра незачем, поэтому ленты опрашиваются
ежечасно. Чтобы новость ушла, нужны два условия сразу: компания действительно
упомянута **и** событие относится к значимой категории. Дефолты и реструктуризации
приходят по всему рынку, а не только по своим бумагам: чужой дефолт — повод
заранее посмотреть на собственные выпуски.

Фильтр по типу бумаги несимметричен намеренно. Держателю облигации идут купоны,
погашения, оферты, дефолты, правовые риски, рейтинги и отчётность, но **не**
дивиденды и допэмиссии. Держателю акции — всё. Категория «правовой риск» (аресты,
уголовные дела, банкротство, санкции) для облигации критична: платить нечем
становится раньше, чем это признают дефолтом.

### Календарь на месяц — первого числа

```
📅 ВЫПЛАТЫ НА МЕСЯЦ
1 октября — 1 ноября
➖➖➖➖➖➖➖➖➖➖

🏦 Альфа
 3 окт · Эмитент 005Р-06R
            ⏳ ставка не объявлена
 8 окт · Эмитент БО-П18
            277,80 ₽
   1 566,40 ₽ — 4 выплаты
   ⏳ ещё по 1 выпуску ставка не объявлена
```

## Установка

Нужен Python 3.14 и macOS с launchd.

```bash
git clone https://github.com/alferova-tv/Jessica-invest-assistant.git ~/Projects/jessica
cd ~/Projects/jessica
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Обёртка, чтобы не писать путь к интерпретатору каждый раз — `~/.local/bin/jessica`:

```sh
#!/bin/sh
exec ~/Projects/jessica/.venv/bin/python -m jessica "$@"
```

Данные и секреты живут **вне репозитория**, в `~/Documents/Tracking/Invest`
(переопределяется переменной `JESSICA_HOME` — этим пользуются пробные прогоны).
Репозиторий можно снести и переустановить, не потеряв ни портфелей, ни истории отправок.

```
~/Documents/Tracking/Invest/
├── config.yaml            секреты, права 600
├── tinkoff/reports/       брокерские выгрузки Т-Инвестиций (xlsx)
├── alpha/reports/         брокерские выгрузки Альфы (zip с xlsx)
├── state/
│   ├── holdings.json      позиции: ISIN, количество, тип, эмитент
│   ├── schedule.json      купоны, погашения, оферты, параметры выпусков
│   ├── sent.json          что уже отправлено — дедупликация
│   └── last_run.json      что уже сделано сегодня
└── logs/
```

`config.yaml` — по этому образцу:

```yaml
telegram:
  token: "нужен от @BotFather"
  chat_id: 000000000

portfolios:
  tinkoff:
    title: "Т-Инвестиции"
    reports_dir: "tinkoff/reports"
  alpha:
    title: "Альфа"
    reports_dir: "alpha/reports"

# За сколько дней до события предупреждать (0 = в день события)
reminders:
  coupon:       [0]
  amortization: [3, 0]
  offer:        [14, 7, 3, 0]
  maturity:     [7, 0]

schedule:
  morning_hour: 9      # час рассылки событий дня, МСК
  market_hour: 10      # час сводки по рынку
  market_weekends: false
  monthly_calendar: true

sources:
  moex_timeout_sec: 3  # оппортунистическая попытка достучаться до Мосбиржи
```

Агент по расписанию — `~/Library/LaunchAgents/com.alferova.jessica.plist`,
`StartInterval` 3600. Перезагрузка после правок:

```bash
launchctl unload ~/Library/LaunchAgents/com.alferova.jessica.plist
launchctl load -w ~/Library/LaunchAgents/com.alferova.jessica.plist
```

`StartInterval` — таймер, а не будильник: он отсчитывает час от загрузки агента,
поэтому сообщение приходит первым проходом после назначенного часа, а не ровно
в 9:00. Если машина спала, пропущенный час догоняется на ближайшем проходе.

Проверить, что всё сошлось:

```bash
jessica doctor
```

## Команды

| Команда | Что делает |
|---|---|
| `jessica doctor` | проверка источников, связи, наличия выгрузок |
| `jessica import` | разобрать брокерские выгрузки → `holdings.json` |
| `jessica refresh` | пересобрать календарь → `schedule.json` (~40 с, 48 HTTP-запросов) |
| `jessica calendar --days 30` | ближайшие выплаты, в терминал |
| `jessica check --dry-run --date ГГГГ-ММ-ДД` | что ушло бы в эту дату |
| `jessica news --dry-run` | новости, без отправки |
| `jessica market --dry-run` | индекс и курс доллара, без отправки |
| `jessica run` | один проход по расписанию (его запускает launchd) |

**Про `--dry-run`.** У `check` и `news` без него проверка отправит владелице
настоящее сообщение и запишет его в `sent.json` — после чего настоящее уведомление
в этот день уже не придёт. У `market` наоборот: отметку в `last_run.json` ставит
только `run`, поэтому вручную запущенная сводка уйдёт лишним сообщением
и утренней не помешает.

Разовые расчёты запускай тем же интерпретатором (`.venv/bin/python`) —
системный Python зависимостей не видит.

## Как это устроено

```
брокерские выгрузки → holdings.py → state/holdings.json
                                          ↓
   sources/smartlab.py → calendar.py → state/schedule.json
                                          ↓
   sources/news.py  →  events.py  →  notify.py  →  Telegram
                          ↑
                    state/sent.json (дедупликация)

   sources/market.py → events.py → notify.py → Telegram   (утренняя сводка)
```

Правило, на котором держится вся конструкция: **логика уведомлений работает
только с `holdings.json` и `schedule.json` и ничего не знает об источниках.**
Смена источника — правка одного файла в `sources/`, а не всей программы.

`run` идемпотентен. `sent.json` хранит ключи `isin|тип|дата|за_сколько_дней|портфель`,
поэтому повторный запуск в тот же час ничего не задваивает. Разовые за день рассылки
отмечаются датами в `last_run.json`.

Состав портфелей приходит **только** из брокерских выгрузок, руками не заносится.
Форматы у брокеров разные настолько, что общей эвристикой не обойтись: в `holdings.py`
два точных парсера и общий запасной. Нераспознанные строки попадают в `skipped`
и печатаются, а не теряются молча.

### Источники

Машина физически в России, но постоянно под европейским VPN, и это определяет
архитектуру целиком.

| Источник | Что даёт | Состояние |
|---|---|---|
| `smart-lab.ru` | купоны, погашения, оферты, номинал, амортизация | рабочий |
| `smart-lab.ru/news/rss` | телеграфные заголовки корпоративных событий | рабочий |
| `thebell.io/feed` | развёрнутые формулировки, больше про макро | заблокирован в РФ, держится на VPN, отваливается чаще прочих — это штатно |
| `iss.moex.com` | значение IMOEX2 | годами давал таймаут, сейчас отвечает; полагаться нельзя |
| `cbr.ru` | официальный курс доллара | рабочий, быстрый |
| `e-disclosure.ru` | официальное раскрытие | **за капчей**, программой не берётся |
| `invest-public-api.tinkoff.ru` | — | таймаут, не используется |

Капчу Jessica не обходит: факт события берётся из ленты, а в сообщение кладётся
ссылка на поиск по компании — открывает её человек.

Всё, что ходит в сеть, переживает разовый таймаут повтором, а не считает его
отказом: VPN изредка обрывает соединение. Ленты и источники сводки опрашиваются
порознь — молчание одного не лишает слова остальных. Увидеть молчащий источник
можно в `jessica doctor`.

## Чего Jessica не умеет

Честный список, чтобы не искать это в коде.

- **Доходности к погашению нет.** Цен покупки и котировок нет вообще — только
  денежные потоки.
- **Даты и суммы амортизационных выплат неизвестны**: источник даёт лишь факт
  амортизации. Такие выпуски помечаются словами.
- **Ставки флоатеров** до объявления показываются как «ставка не объявлена».
- **ОФЗ ищутся по биржевому коду** (`SU26253RMFS3`), а не по ISIN.
- **Тестов нет**, `tests/` пуста.
- **`pdfplumber` не установлен** — ветка разбора PDF в `holdings.py` сработает
  только после `pip install pdfplumber`.
- **`browser.py` (Playwright) написан и работает, но в рабочем цикле не задействован**:
  единственный источник, ради которого он был нужен, закрыт капчей.

### Известные шероховатости

- **Ложные срабатывания в новостях по коротким названиям.** Основа названия
  режется до трёх букв, и «Озон» превращается в «озо», которое сидит внутри слова
  «прогнозом» — рейтинговая новость про чужую компанию приезжает как своя.
  Лечится либо более длинной основой для коротких имён, либо поиском по границе слова.
- **`fetch_coupons` не повторяет запрос после таймаута**, в отличие от новостей
  и сводки. Разовый сбой smart-lab отдаёт пустой список, и `refresh` молча урежет
  `schedule.json` по этому выпуску.

## Отладка

```bash
jessica doctor                       # первое, что стоит сделать
tail -f ~/Documents/Tracking/Invest/logs/jessica.log
tail -f ~/Documents/Tracking/Invest/logs/launchd.log
launchctl print gui/$(id -u)/com.alferova.jessica | grep -E "state|last exit|runs"
cat ~/Documents/Tracking/Invest/state/last_run.json   # что уже сделано сегодня
```

Уведомление не пришло — сначала посмотри `sent.json` и `last_run.json`: скорее
всего, оно уже помечено отправленным (например, пробным прогоном без `--dry-run`).

Чтобы прогнать что-нибудь на отдельной копии данных, не трогая рабочую:

```bash
cp -R ~/Documents/Tracking/Invest /tmp/jessica-test
JESSICA_HOME=/tmp/jessica-test .venv/bin/python -m jessica check --dry-run
```
